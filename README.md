# Bing 积分助手（bingbot）

一个跑在手机本机的 Android 无障碍自动化工具，自动完成 Microsoft Rewards 每日任务：**搜索积分、阅读积分、签到连击、每日活动卡片**。

不需要连电脑，不需要 AutoX.js / Tasker 之类的第三方运行时，装完就是一个 41 KB 的原生 APK，开机自启 + 定时触发，全程在手机上自己跑完。

> 📦 想要现成的 APK，去 [Releases 页面](https://github.com/zjf-max/bing-rewards-bot/releases) 下载。

```
bing-rewards-bot/
├── AndroidManifest.xml
├── build.sh            # 一键构建，不依赖 Gradle
├── test.sh             # 真机调试助手
├── src/com/a11y/bingbot/
└── res/
```

## 它解决什么问题

必应 App 的积分页每天要求：搜索若干次、阅读若干篇文章、连续签到、点几张活动卡。这些操作本身没有难度，但每天都要做，而且必须用真实的 App 交互（点搜索框、打关键词、点进文章停留几秒）。

常见的三种做法各有短板：

| 方案 | 问题 |
|---|---|
| 脚本 + ADB 连电脑 | 每天都得开着电脑、插着线 |
| AutoX.js / Tasker | 要装额外运行时，依赖它的 API 版本；脚本权限受限 |
| **无障碍服务 APK** | 只用系统原生 API，无第三方依赖，可开机自启、可精确闹钟 |

本项目选的是第三条。手机本身就是执行端，电脑只在开发和调试时需要。

## 功能与完成度

| 模块 | 状态 | 说明 |
|---|---|---|
| 搜索积分 | ✅ 真机验证 | 单次约 **5.4 s**，自动轮换关键词避免重复查询不计分 |
| 阅读积分 | ✅ 真机验证 | 单篇约 **8–14 s**（打开 1 s + 停留 5–8 s + 页面校验） |
| 每日定时 | ✅ 真机验证 | 精确闹钟，实测在设定时刻 **+22 ms** 触发，触发后自动排次日 |
| 断线重试 | ✅ 真机验证 | 无障碍未就绪时不放弃，10 分钟后重试，服务重连后自动补跑 |
| 签到连击 | ⚠️ 开发中 | 已能进奖励页并定位到「今天」那一格，点击命中率待校准 |
| 每日活动卡 | ⚠️ 开发中 | 已能定位卡片并跳转，返回后 +10 结算，卡片消失逻辑待加固 |

## 环境要求

**手机端**

- Android 11 及以上（`minSdkVersion 30`，`targetSdkVersion 34`）
- 已登录必应 App 并正常显示 Rewards 积分页
- 小米 / 红米等国产 ROM 需要额外放行后台（见[安装与授权](#安装与授权)）

**构建端**

- JDK 11 或更高（用到 `javac` / `keytool`）
- Android SDK：
  - `build-tools/34.0.0`（`aapt2`、`zipalign`、`lib/d8.jar`、`lib/apksigner.jar`）
  - `platforms/android-36/android.jar`
- Python 3（打包 dex 时用 `zipfile` 模块，仅此一处）
- Bash（Windows 下用 Git Bash）

不需要 Gradle、不需要 Android Studio。

## 构建

```bash
cd bingbot
./build.sh
```

如果 SDK 或 JDK 不在默认位置，用环境变量指定：

```bash
ANDROID_SDK=/path/to/android-sdk \
BT_VERSION=34.0.0 \
BINGBOT_JDK=/path/to/jdk \
./build.sh
```

嫌每次都写太长，就在 build.sh 同目录建一个 `local.env`（已被 `.gitignore` 排除，不会进仓库）：

```bash
ANDROID_SDK=/path/to/android-sdk
BINGBOT_JDK=/path/to/jdk
ADB=/path/to/adb          # test.sh 也读这个文件
```

默认查找顺序：`$ANDROID_SDK` → `$ANDROID_HOME` → `~/Android/Sdk`；JDK 取 `$BINGBOT_JDK` → `$JAVA_HOME`。

脚本会先做一遍预检，缺文件时直接报出具体路径。六个步骤：

| 步骤 | 命令 | 产物 |
|---|---|---|
| 1 | `aapt2 compile --dir res` | `build/res.zip` |
| 2 | `aapt2 link --manifest` | `build/base.apk` + `R.java` |
| 3 | `javac --release 11` | `build/classes/**` |
| 4 | `d8 --min-api 30` | `build/dex/classes.dex` |
| 5 | Python 写入 dex + `zipalign` | `build/app-aligned.apk` |
| 6 | `apksigner`（首次自动生成 `debug.keystore`） | `bingbot.apk` |

`debug.keystore` 口令固定为 `android`，只在缺失时生成，已被 `.gitignore` 排除。换成自己的正式签名只需替换这个文件。

## 安装与授权

```bash
adb install -r -g bingbot.apk
```

然后按顺序完成四件事（前三步 `bash test.sh install` 会自动做掉）：

1. **开启无障碍服务**
   设置 → 无障碍 → 已下载的服务 → Bing 积分助手 → 开启

2. **加入电池优化白名单**
   `adb shell cmd deviceidle whitelist +com.a11y.bingbot`
   或手动：设置 → 应用 → Bing 积分助手 → 省电策略 → **无限制**

3. **允许自启动**
   小米：设置 → 应用设置 → 应用管理 → Bing 积分助手 → 自启动 打开

4. **在任务切换器里锁定**
   打开应用后进入最近任务，长按卡片加锁，防止系统清理后台

第 2–4 步是国产 ROM 上能否稳定每日触发的关键。省电策略为「智能限制」时，进程会在夜间被回收，闹钟虽然照常触发，但无障碍服务没连上，任务会走重试逻辑而不是立即执行。

## 使用

### 界面

打开应用后是单页配置：

- **三行状态**：无障碍服务是否连接、电池优化是否已忽略、今日执行记录
- **时间输入**：`09:00` 这样的 24 小时制，点「保存时间」写入并重排闹钟
- **启用每日自动运行**：勾选后立即登记闹钟，取消则撤销
- **立即运行**：手动跑一次完整流程
- **清空日志**：清空内存日志缓冲区
- **扫描当前页面（排错用）**：把当前无障碍节点树导出到 `Android/data/com.a11y.bingbot/files/dump.txt`

### 通过 ADB 触发（便于调试）

```bash
# 完整流程（搜索 5 次 + 阅读 10 篇）
adb shell am start -n com.a11y.bingbot/.MainActivity --es mode force

# 只做签到 + 每日活动
adb shell am start -n com.a11y.bingbot/.MainActivity --es mode rewards

# 转储当前所有窗口的节点树
adb shell am start -n com.a11y.bingbot/.MainActivity --es mode dump

# 设定每天 09:00 自动运行
adb shell am start -n com.a11y.bingbot/.MainActivity --ez auto true --ei hour 9 --ei minute 0

# 清除「今日已运行」记录，让任务可以再跑一次
adb shell am start -n com.a11y.bingbot/.MainActivity --ez reset true
```

`force` 模式不读今日进度，固定做 1 次搜索 + 1 篇阅读，用于交互链路回归测试。

### 辅助脚本

```bash
bash test.sh install   # 安装 + 开无障碍 + 关电池优化 + 启动界面
bash test.sh enable    # 只重新开启无障碍
bash test.sh run       # 清日志、冷启动应用
bash test.sh logs      # 看最近 60 行运行日志
bash test.sh state     # 看无障碍状态与前台应用
```

## 工作原理

```
AlarmManager（每天 09:00，setExactAndAllowWhileIdle）
        │
        ▼
   AlarmReceiver ──► Engine.start("auto")
        │                  │
        │      ┌───────────┴────────────┐
        │      ▼                        ▼
        │   唤醒屏幕                无障碍未连接？
        │   检查是否锁屏                 │
        │      │                        └─► 10 分钟后重试
        │      ▼
        │   启动必应 App
        │      │
        │      ├─► 奖励页：签到 → 逐张点活动卡 → 回退
        │      │
        │      ├─► 读进度（搜索 X/Y、阅读 M/N）
        │      │
        │      ├─► 搜索 N 次（N = ⌈(Y−X)/3⌉）
        │      ├─► 阅读 M 篇（M = ⌈(N−M)/3⌉）
        │      │
        │      └─► 复检进度，全满则标记今日完成
        │
        ▼
   排下一次闹钟（次日同一时刻）
```

几条设计取舍：

**为什么次数是除以 3。** 必应每次搜索/阅读大约给 3 分，同一次操作给分有上限。按差额除以 3 估算次数，比固定跑满 30 次更快，也不会欠账。

**为什么关键词要轮换。** 重复的查询不再计分，这是实测结论。词库是 52 个主题 × 16 个修饰词，再加 1/3 概率随机年份，组合空间约 1.3 万种，用计数器加纳秒时间驱动取模，保证短时间内不撞。

**为什么有服务内轮询。** 精确闹钟在国产 ROM 上可能被「智能省电」吞掉。无障碍服务本身常驻内存，每 30 s 检查一次：只要当前时间落在 `[目标时刻, 目标时刻 + 120 min]` 区间、今天还没跑过、且引擎空闲，就当闹钟没来，直接补跑。

**签到与活动卡的机制。** 点「每日活动」卡片会直接打开一个搜索结果页，返回后 +10 积分到账、卡片消失。签到是连击式，点今天那一格给固定分（本例 15 分），且这 15 分**不占**每日 90 分的额度——这是页面实测出来的，不是文档写的。

## 关键技术点

这一节记录开发和调试过程中踩到的坑，也是这套代码能跑起来的原因。

### 1. 用无障碍而不是 ADB input

`adb shell input text` 走的是 IME 注入，会被输入法的联想候选和自动纠错干扰，且需要电脑。无障碍服务用两条原生通道：

- `ACTION_SET_TEXT` 直接写入 EditText，绕过输入法
- `dispatchGesture` 发送真实触摸事件，绕过 `ACTION_CLICK` 在某些自绘控件上无效的问题

### 2. 搜索提交的五级降级链

必应首页的搜索框敲完字后，没有可靠的「提交」按钮暴露在无障碍树里。代码按成功率排了个顺序，逐级尝试，前一级失败才走下一级：

| 顺序 | 策略 | 原理 |
|---|---|---|
| 0 | 点输入法右下角 | 按 IME 窗口几何比例盲点「搜索/回车」键 |
| 1 | 点输入法右下角（偏下） | 同上，纵向下移一点，适配不同键盘布局 |
| 2 | `ACTION_IME_ENTER` | 标准无障碍语义动作 |
| 3 | 点页面「搜索」按钮 | 部分版本有 |
| 4 | `bing://search?q=...` 深链 | 直接落到结果页，跳过输入 |

**为什么必须盲点。** 实测微输入法（WeType）整个键盘在无障碍树里**只有一个可点击节点**：

```
FrameLayout #rk [0,1891][1200,2590] CLICK
```

没有任何按键盘位级别的节点，所以 `ACTION_IME_ENTER` 这个标准动作在这里不生效。唯一可行的办法是按窗口尺寸算比例——`x = right − 6% 宽`，`y = bottom − 10.5% 高`，正好落在右下角搜索键上。

**还有一个前提。** 只调 `ACTION_SET_TEXT` 不会让输入法绑定到这个输入框，`mServedView` 仍为 `null`，此时任何 ENTER 动作都没有作用对象。所以必须先用手势**真点一下 EditText**，让输入法真正弹出来并绑定，再写文本、再提交。

### 3. 新闻卡片的识别不依赖坐标

WebView 里的节点在离屏时上报的 bounds 是 `[0,0][0,0]`，按坐标找卡片会全军覆没。代码改成**结构化判断**：按深度优先顺序扫描，一个满足下面条件的可点击节点就是卡片：

- `content-desc` 长度 ≥ 12（是标题而不是按钮）
- 在它之后 18 个节点之内，出现一个匹配 `^\d+\s*(小时|分钟|天|分|秒)$` 的时间文本
- 在遇到下一个卡片或「广告 / 广告选项」标记之前出现

时间文本是每张卡片右下角都会渲染的元信息，用它当锚点比坐标稳得多。

### 4. 首页 feed 需要先展开

必应首页的信息流初始只渲染约 620 px 高的一条，卡片全在下面但不在树里。`ensureFeedExpanded()` 会反复上滑，直到 `sa_hp_feed_container` 的高度超过屏幕的 42%，再开始选卡。

### 5. 进度解析要对「今天已满」容错

满额后，页面上的「搜索以赚取」那一行会整个消失而不是显示 `30/30`。所以解析器同时处理两种形态：找到就取 `已赚取 X` / `需要 Y`，找不到就用历史记录里的最大值兜底，并把本次最大值持久化到 SharedPreferences。

### 6. 不能有匿名内部类

构建链里 `d8` 处理 `Outer$1.class` 这类匿名内部类时会崩：

```
NullPointerException: Cannot invoke "String.length()" because "<parameter1>" is null
```

字节码本身是合法的（`javap` 验证 `outer_class_info_method_index = 0`），换 `--release` 版本也没用。解决办法是全项目**不使用匿名类**，一律用具名静态内部类（`Engine.Worker`、`BingA11yService.Ticker`、`MainActivity.Poller`）。

### 7. 读者可能遇到的两个小问题

- **`javac: command not found`**：`PATH` 里不能直接塞 Windows 形式的盘符路径（反斜杠或 `X:/`），Git Bash 解析不到。脚本会用 `cygpath` 转成 POSIX 路径，所以 `local.env` 里写 `/d/...` 或 `D:/...` 都可以。
- **`debug.keystore` 口令**：固定 `android`，删掉后构建脚本会自动重建。

常见现象对照：

| 现象 | 原因 | 处理 |
|---|---|---|
| `无障碍服务未连接` | 服务被系统回收或手动关闭 | 重新开启；应用会在 10 分钟后重试 |
| `手机锁屏中，无法点击` | 到点时屏幕锁着 | 关闭锁屏密码，或到点前解锁亮屏 |
| `! 找不到搜索框` | 停在了应用面板而不是首页 | 按返回回首页；`pageKind()` 已区分两种页面 |
| `! 点了 Rewards 但没进页面` | 页面还在异步加载 | 已有 6 轮轮询；仍失败则是网络问题 |
| `短停留未结算，切成长停留 30-44s` | 当天阅读结算规则变严 | 自动降级，无需干预 |
| 搜索成功但积分不涨 | 关键词重复或当日已满 | 看日志里的进度行 |

## 已知限制

- **分辨率适配**：所有坐标都按屏幕比例计算，但只在 1200×2670（小米 14）上实测过。其他分辨率理论上成立，盲点输入法的比例可能需要微调。
- **语言/版本**：文案匹配（`搜索以赚取`、`签入`、`Day 1`、`所有应用`）基于当前中文版必应 App，改版或换语言后需要同步更新。
- **签到与每日活动**：仍在校准，见[功能与完成度](#功能与完成度)。
- **账号切换**：换号后建议点一次「清空日志」并在设置里清「今日已运行」记录，让引擎重新读进度。
- **自动化本身的风险**：见下。
